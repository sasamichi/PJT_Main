## 1. プロジェクト基本方針（スコープとアーキテクチャ）

### 1.1 地図表現・データ形状・変遷の扱い（K3・Q7回答）
- **点（Point）と一覧表のみで構成する**。
- 自治体の境界線（ポリゴン・面）や、路線の詳細な走行軌跡（ライン・線）の幾何データ（GeoJSON等）は保持しない。
- 自治体は「政庁所在地（緯度・経度の点）」、交通網は「路線（メタデータ）」と「拠点（駅・IC等の点）」および「繋がり（順序関係）」で表現する。
- 過去の旧自治体（合併前の旧町村等）や廃線・廃駅を扱う場合も、当時の所在地（点）と一覧表のみで表現する。
- **時間の持ち方**: 過去データの収集は工程の後ろになるため、現段階ではスキーマ（`時代区分` と `状態`）をそのまま維持し、開始年・終了年等の詳細列の拡張は過去データ収集時に改めて検討する。
- **理由**: データ容量の肥大化、GIS処理の過度な複雑化、初心者にとっての保守難易度を劇的に引き下げ、軽量かつ軽快な動作を維持するため。

### 1.2 データ管理・保存方式（Q1回答）
- **正本はローカルの構造化CSVマスタ（`data/master/*.csv`）** とする。
- 将来的な大規模データ化（数十万〜数百万レコード）を考慮し、Googleスプレッドシートへの全面依存は行わず、閲覧・手作業確認用としてのみ利用する。
- **Git / GitHub連携**:
  - ローカルに Git を導入し、データやコードの変更履歴を厳格に管理する。
  - 将来的なバックアップおよび「初期の簡易Webサイト公開（GitHub Pages）」の展開を視野に入れたリポジトリ構成とする。
- アプリの高速検索用として、必要に応じてCSVからローカルのSQLiteキャッシュを自動生成する。

### 1.3 収集対象範囲（K1・Q3回答・フィードバック）
- **交通網の範囲**:
  - **対象外**: インフラライン（電気・水道・パイプライン等）。
  - **鉄道**: JR、大手・準大手・地方私鉄、公営地下鉄、路面電車。
  - **道路**: 高速道路、一般国道、主要地方道（各都道府県指定の幹線道路のみ）。
    - ※一般県道、市町村道、林道、農道は初期自動取得から全件除外（将来の探索時に気になったもののみ個別追加）。
  - **バス**: **都市間長距離バス ＋ 空港連絡バス**（市内一般路線バス・コミュニティバスは除外）。
  - **索道（ロープウェイ・ゴンドラ等）**: オーストリア・スイスの収集過程で収集範囲を改めて検証・決定する。
  - **空海**: 旅客空港、主要港湾。
- **地域・区域の範囲**:
  - 初期データ: 各国の行政区画（国・最上位広域区画・基礎自治体）。
  - 将来の追加対象: 最新の**気象等の予報区**（気象庁の一次細分区域など）。

### 1.4 多言語・地名表記ルール（Q4回答）
- 日本語版WikipediaやWikidataに日本語ラベルが存在しない外国地名・施設名について、**「日本語名」列は空欄とする**。
- ドイツ語等の現地名称は「公用語名」列にのみ保持し、日本語名列への外国語混入を根絶する。

### 1.5 進行優先順位・作業順の一本化（K6・K1・Q5回答）
- **優先順位の4原則**:
  1. **時代軸**: **「現代（現存）」を最優先**。過去・計画データは後回しとし、現代の骨格完成後に「探索」を通じて追加する。
  2. **データ階層軸**: **「自治体（枠組み）」→「交通網（路線・拠点）」→「繋がり（駅順序）」** の順に進める。
  3. **地域軸**: **「全世界の国・最上位行政区画（州・県等）」を先行配備** → その後、**「1国ずつ（日本 → オーストリア → 韓国 → 台湾...）」** 基礎自治体と交通網を完結させる。
  4. **地理的進行順序**:
     - 構想にあった「北海道から南へ」という曖昧な表現は基準から削除する。
     - 繋がりデータの整備や探索の進行は、客観的な**「公的自治体コード順（日本の場合は01北海道〜47沖縄、海外も公的行政コード順）」** で整然と進める。
- **進行フェーズ（ロードマップ）**:
  - **フェーズ1（基盤確立 ＆ 先行実証）**:
    - 全世界の「国（約200カ国）」＋「最上位行政区画（約3,000〜4,000件）」を先行収集。
    - 日本・オーストリアの基本データ（現存自治体・交通網・函館本線繋がり）の完成。
    - Webサイト・探索ツールの初期公開。
  - **フェーズ2（国内の繋がり展開 ＆ 探索の開始）**:
    - 自治体コード順（01北海道〜）に国内鉄軌道・主要道路の繋がり（`route_nodes.csv`）を構築。
    - 探索（バーチャル旅行）を開始し、気になった過去データや名所、一般県道等を手動追加。
  - **フェーズ3（海外への本格展開）**:
    - 韓国・台湾・スイス等、1国ずつ事前調査 → 自治体・交通網・繋がりの構築。

### 1.6 Webサイトの対象者・早期立ち上げと発信媒体（K5・Q6回答）
- 対象者は「交通・地理好きの一般の方」を主とし、「自分自身の記録・趣味」を兼ねる。
- 専門的・学術的に偏りすぎず、日本語で直感的にわかりやすく、操作しやすいインターフェースを最優先とする。
- **Webサイトの早期立ち上げ**: 収集したデータの一部公開・検索ダッシュボードとして、GitHub Pages等の無料・高速な静的配信を活用し、早期の立ち上げ・公開を目標とする。
- **発信媒体の一本化**: 初期の一人運用における負荷を抑えるため、**「X（進捗・小ネタ）」および「note（まとまった探索記事・地図埋め込み）」の2媒体に絞る**（ThreadsやFacebookは初期は休止）。

### 1.7 権利・外部サービス規約対応（K4・Q8回答）
- **Google Maps / ストリートビュー**:
  - 画像（写真・キャプチャ等）はローカルDBに直接保存・再配布しない。
  - サイトやSNS、noteでは「公式URLリンク」または「公式埋め込みタグ（iframe）」を用いて表示し、利用規約を遵守する。
  - 探索時にGoogle Maps / ストリートビューで現地を目視確認し、手作業で正確な座標を入力・修正する行為は、通常の地図参照（事実の入力）として許容・安全とする（※APIによる機械的一括スクレイピングは行わない）。
- **Webサイト・探索ツールの地図表示（Leaflet / MapLibre）**:
  - 背景地図として国土地理院タイルやOpenStreetMap（OSM）等のオープン地図タイルを表示し、その上に自作マスタ（駅・IC・役所等の点）をプロットする手法を採用する（ライセンス上完全に合法で、自作DBにODbLが感染しない）。
  - 地図の隅に指定のクレジット（例: `© OpenStreetMap contributors`、`国土地理院`）を明記する。
  - **他国の地図タイル（例: オーストリアの basemap.at 等）の選定方針**: 各国の事前調査時、または実装時にその都度決定・確認する。
- **オープンデータ・Wikipedia/Wikidataの扱い**:
  - Wikidata: CC0（パブリックドメイン）のため、自由に収集・DB保存・Web公開可能。
  - 国土数値情報（国交省）: 政府標準利用規約2.0（CC BY互換）に基づき、出典を明記して自由利用。
  - Wikipedia: 本文を引用・転載する場合は記事URLと「出典：Wikipedia」を明記する。
  - GeoGuessr: 公式機能（Map Maker等）の通常利用範囲内とし、非公式スクレイピングは行わない。

### 1.8 運用費用・システム構成・収益化体制（K5・Q9回答）
- **月額上限1万円以内**を厳守。
- 高額な商用クラウドDB（Cloud SQL、Firebase有料プラン等）や有償APIの継続利用は原則行わない。
- ローカルPython環境、オープンデータ（Wikidata、国交省オープンデータ等）、GitHub（無料枠）を主軸とする。
- **収益化による費用回収**: Webサイト（AdSense広告、交通・旅行アフィリエイト）やnote（一部有料記事等）を活用し、固定費（ドメイン代等）を上回る収益を確保できる体制を目指す。
- **データベースと画面表示（グラフビュー・ナレッジパネル）の実現方式**:
  - 高度で保守が困難なグラフDB（Neo4j等）は導入せず、**正本CSV ＋ 高速検索用SQLiteキャッシュ ＋ 繋がり表（`route_nodes.csv`）に一本化**する。
  - **ナレッジパネル**: CSV/SQLiteから取得した属性情報をHTMLカードとして直接表示する（グラフDB不要）。
  - **グラフビュー（ネットワーク図）**: 手元のCSVから変換した軽量JSONをブラウザに渡し、JavaScriptライブラリ（Vis.js、Cytoscape.js等）で描画する。高額なサーバーを立てずに、無料かつ軽快にインタラクティブな関係図を実現する。

### 1.9 用語の定義（K2確定）
- **交通網**:
  - 人や貨物の移動を担う公的交通インフラ（鉄道、高速・国道・主要地方道、都市間長距離バス＋空港連絡バス、旅客空港、主要港湾、索道）。
  - ※供給インフラ（電気・水道・パイプライン等）、一般市内路線バス、一般県道、市町村道、林道、農道、自転車道は対象外。
- **区間**:
  - 路線上において隣り合う拠点（駅・IC等）と拠点の間。
  - 営業キロ・路線内番号・区間別称（本線・支線等）の属性を持つ順序関係を指し、地図上の詳細走行軌跡（ラインGeoJSON）は持たない。
- **繋がり**:
  - 以下の関係性を指す：
    1. **路線の順序関係**: 路線における拠点の並び順（`route_nodes.csv`）。
    2. **拠点と地域の所在関係**: 拠点がどの自治体に属するか（`municipality_id`）。
    3. **路線同士の接続関係**: 同一駅における複数路線の乗換、および分岐駅・合流駅の役割。
    4. **自治体同士の繋がり**: 姉妹都市・友好提携都市等（※収集の優先度は低く、将来の拡張対象）。
- **変遷・時代区分**:
  - 時代区分は優先度を考慮し、以下の**3区分に集約**する：
    1. **前近代**: 古代・中世・近世（江戸時代・近世以前）を1つに統合。
    2. **近代**: 明治維新〜戦前（おおむね第二次世界大戦終結まで）。
    3. **現代**: 戦後〜現行。
### 1.10 個別方針と今後の検討項目（K7確定）
- **構想原本の保護と決定事項の運用**:
  - 起案時の原本 `構想.md` は変更せず永久保存する。
  - 方針の確定・追加・修正はすべて本ファイル（`docs/決定事項.md`）に集約して管理する。
- **Webサイトの対象者・言語**:
  - 対象者は「交通・地理好きの一般の方（半分は自分の趣味・記録）」とし、直感的で操作しやすい日本語インターフェースを基本とする。
- **データベース・探索・GeoGuessrの3層構造（検討項目）**:
  - **データベース（幹・基盤）**: 交通網・自治体の客観的な正本データ（清潔に維持）。
  - **探索（活動・インプット）**: マスタを活用した趣味のバーチャル旅行。
  - **GeoGuessr（アウトプット・制作）**: 中世史跡や交通難所などをテーマとしたオリジナルマップ制作活動。
  - ※上記3層の具体的な連携・運用ルールについては、フェーズ2（探索開始時）の検討項目としてキープし、実践を通じて具体化する。

## 2. データ品質保証・作業フロールール

### 2.1 AIの自己申告判定の禁止（F1・問題2対策）
- 検査スクリプトを実行せずに人間またはAIが手書きで「合格」と記述することを禁止する。
- すべての判定は `scripts/validators/check_integrity.py` を通じて客観的なログ・数値として出力する。

### 2.2 精度基準マスタの運用
- すべての収集対象について、`docs/精度基準マスタ.csv` に「公的基準件数」「出典機関・URL」「確認日」を記録する。
- 公式根拠のない推定値は「基準未確定」と明記し、安易に合否判定を下さない。

### 2.3 抜き取り確認（Q2回答）
- 機械的チェック（件数、座標、ID重複）に加え、各段階の完了時にスクリプトが「抜き取り確認レポート（Google Mapsリンク付き約20件）」を出力する。
- ユーザーによる目視確認・承認を経てから次のフェーズへ進む。

### 2.4 IDの永続化ルール（問題1対策）
- 一度発行したID（`JP-ND-000001` 等）は、再収集時にも**絶対に変更・再利用しない**。
- 照合キー（Wikidata QID、公的自治体コード、または国コード+種別+正規化名称）により既存レコードと突合し、新規レコードのみ最大連番+1で採番する。
- 収集元から消えたレコードは削除せず、`状態 = 要確認` または `廃止` に変更して履歴を残す。

## 3. ツール・画面構成の確定仕様（2026-10-16確定）

### 3.1 机上探索ツールのWeb GIS一本化
- **方針**: 旧来のStreamlit版探索画面を撤去し、HTML5/JavaScript + Leafletによる「**机上探索 Web GIS** (`http://localhost:8080/`, `web/explorer/`)」へ完全に一本化する。
- **画面分割**: 「🔲 1画面」「◫ 2画面 (左右)」「⊟ 2画面 (上下)」「⊞ 4画面」の4パターンに集約（3画面は廃止）。
- **マーカー色差別化**:
  - 🔵 **マスタ登録交通拠点**: 青 (`#2563eb`)
  - 🟠 **探索追加ポイント (自分)**: 橙 (`#f97316`)
  - 🔴 **探索追加ルート (自分)**: 赤色実線 (`#ef4444`)
  - 🟣 **Wikidata 史跡・旧跡**: 紫 (`#a855f7`)
- **ルート描画機能**: 〰️ ツールにより連続クリック描画・ダブルクリック確定・頂点ドラッグ微調整・右クリック削除・GeoJSON座標列保存に対応。
- **データ修正・削除**: 地図上のピンをドラッグして位置保存、編集・削除ダイアログ。
- **Wikidata自動表示**: 初期状態常時ON。中心周辺15kmのスポットを自動フェッチ。

### 3.2 データ管理 & 品質保証ツールの仕様統一
- **特化方針**: 探索機能をWeb GISへ譲渡し、管理ツール（Streamlit `tools/admin.py`）は「データ管理 & 品質保証」に専念。
- **機能構成（5タブ）**:
  1. 📈 **収集進捗管理**: 国レベル限定（上位行政区画収集後に地域レベルを検討するため、現状は国レベルで管理）。
  2. 🛡️ **精度管理・公的基準突合**: `docs/精度基準マスタ.csv` との動的突合・合否判定。
  3. 🔍 **抜き取りチェック**: 20件抽出とGoogleマップリンクによる人間確認。
  4. ⚠️ **不整合・要修正データ**: 重複、国境逸脱、迷子外部キーの自動検出。
  5. 📚 **マスタデータ台帳**: CSVの直接閲覧・編集・保存。
- **デザイン連動**: 黒背景トグル（ダークテーマCSS適用）、上部余白最適化（`padding-top: 4.8rem` によるヘッダー潜り込み防止）。

### 3.3 一般公開用 Webサイト（プロトタイプ）仕様
- **月額0円ホスティング**: バックエンド不要の完全静的配信（GitHub Pages対応）。
- **静的JSONエクスポーター**: `scripts/builders/export_public_data.py` によりマスタCSVから公開用軽量JSONを一括生成。
- **全251カ国選択UI**: メイン画面の「🌍 国・地域」タブおよび上部バーの「🔍 全251カ国から選ぶ...」検索セレクトボックス。
- **表示モード切替（地図ビュー vs 階層ビュー）**:
  - **🗺️ 地図ビュー**: 一覧リストとLeaflet連動地図の2カラム構成。
  - **📖 階層ディレクトリビュー (地図なし)**: 地図を表示せず、パンくずリスト（`世界 ➔ 国 ➔ ジャンル ➔ 名称`）を見ながら台帳・百科事典のように深く辿る全幅画面。
- **ナレッジパネル（詳細情報表示枠）**:
  - 路線・自治体・拠点を選択した際に、Google風の詳細情報パネルを展開（地図ビュー時は右側ドロワー、階層ビュー時は全幅カード）。
  - 多言語表記、諸元テーブル、駅順序シーケンス、および **Google Maps / Wikipedia (日・英) / Wikidata / OSM / 公式サイトへの直行ボタン**。

### 3.4 統合ランチャーと相互連携
- **ランチャー (`run.py` / `起動.bat`)**: ポート8080/8501の自動解放、探索Web GIS・管理画面・公開サイトの統合起動。
- **相互リンク**: 全ツールのヘッダーに相互リンクボタンを設置し、ツール間を自由に移動可能。
