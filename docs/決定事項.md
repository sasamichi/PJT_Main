## 1. プロジェクト基本方針（スコープとアーキテクチャ）

### 1.1 地図表現・データ形状（Q7回答）
- **点（Point）と一覧表のみで構成する**。
- 自治体の境界線（ポリゴン・面）や、路線の詳細な走行軌跡（ライン・線）の幾何データ（GeoJSON等）は保持しない。
- 自治体は「政庁所在地（緯度・経度の点）」、交通網は「路線（メタデータ）」と「拠点（駅・IC等の点）」および「繋がり（順序関係）」で表現する。
- **理由**: データ容量の肥大化、GIS処理の過度な複雑化、初心者にとっての保守難易度を劇的に引き下げ、軽量かつ軽快な動作を維持するため。

### 1.2 データ管理・保存方式（Q1回答）
- **正本はローカルの構造化CSVマスタ（`data/master/*.csv`）** とする。
- 将来的な大規模データ化（数十万〜数百万レコード）を考慮し、Googleスプレッドシートへの全面依存は行わず、閲覧・手作業確認用としてのみ利用する。
- **Git / GitHub連携**:
  - ローカルに Git を導入し、データやコードの変更履歴を厳格に管理する。
  - 将来的なバックアップおよび「初期の簡易Webサイト公開（GitHub Pages）」の展開を視野に入れたリポジトリ構成とする。
- アプリの高速検索用として、必要に応じてCSVからローカルのSQLiteキャッシュを自動生成する。

### 1.3 収集対象範囲（Q3回答・フィードバック）
- **林道・農道は全件削除・収集対象外** とする。
- **都道府県道（都道・道道・府道・県道）の扱い**:
  - **一般県道（番号100番台以降等の一般路線）は全件削除・初期自動取得の対象外** とする。
  - **主要地方道（各都道府県指定の幹線道路）のみを対象** とする。
  - ※北海道道が完全に欠落していた過去の反省を踏まえ、安易な「番号120以下」などの正規表現ルールは廃止し、必ず事前調査（`docs/research/JP_道路_制度調査.md`）で全都道府県の付番・指定状況を整理してから取得する。
  - 一般県道や林道・農道は、将来の「探索（バーチャル旅行）」時に気になったもののみ個別追加する。

### 1.4 多言語・地名表記ルール（Q4回答）
- 日本語版WikipediaやWikidataに日本語ラベルが存在しない外国地名・施設名について、**「日本語名」列は空欄とする**。
- ドイツ語等の現地名称は「公用語名」列にのみ保持し、日本語名列への外国語混入を根絶する。

### 1.5 進行優先順位（Q5回答）
- **新規の国（韓国・台湾・スイス等）のデータ収集はすべて凍結**する。
- 以下の順序で厳格に進める：
  1. 土台基盤の修復（ID永続化、自動検査スクリプト、精度基準マスタ）
  2. 事前調査（主要地方道等の公的指定ルール）
  3. クリーンデータの再取得（日本・オーストリア）
  4. 繋がりマスタ（`route_nodes.csv`）の構築（北海道先行）
  5. アプリ改修およびWeb公開準備

### 1.6 Webサイトの対象者・コンテンツ（Q6回答）
- 対象者は「交通・地理好きの一般の方」を主とし、「自分自身の記録・趣味」を兼ねる。
- 専門的・学術的に偏りすぎず、日本語で直感的にわかりやすく、操作しやすいインターフェースを最優先とする。

### 1.7 権利・外部サービス規約対応（Q8回答）
- Google Maps、ストリートビュー、航空衛星写真等の画像・データをローカルDBに直接保存・再配布しない。
- サイトやSNS、noteでは「公式URLリンク」または「公式埋め込みタグ（iframe）」を用いて表示し、利用規約を遵守する。

### 1.8 運用費用の上限（Q9回答）
- **月額上限1万円以内**。
- 高額な商用クラウドDB（Cloud SQL、Firebase有料プラン等）や有償APIの継続利用は原則行わない。
- ローカルPython環境、オープンデータ（Wikidata、国交省オープンデータ等）、GitHub（無料枠）を主軸とする。

## 2. データ品質保証・作業フロールール

### 2.1 AIの自己申告判定の禁止（F1・問題2対策）
- 検査スクリプトを実行せずに人間またはAIが手書きで「合格」と記述することを禁止する。
- すべての判定は `scripts/validators/check_integrity.py` を通じて客観的なログ・数値として出力する。

### 2.2 精度基準マスタの運用
- すべての収集対象について、`docs/精度基準マスタ.csv` に「公的基準件数」「出典機関・URL」「確認日」を記録する。
- 公式根拠のない推定値は「基準未確定」と明記し、安易に合否判定を下さない。

### 2.3 抜き取り確認（Q2回答）
- 機械的チェック（件数、座標、ID重複）に加え、各段階の完了時にスクリプトが「抜き取り確認レポート（Google Mapsリンク付き約20件）」を出力する。
- ユーザーによる目視確認・承認を経てから次のフェーズへ進む。

### 2.4 IDの永続化ルール（問題1対策）
- 一度発行したID（`JP-ND-000001` 等）は、再収集時にも**絶対に変更・再利用しない**。
- 照合キー（Wikidata QID、公的自治体コード、または国コード+種別+正規化名称）により既存レコードと突合し、新規レコードのみ最大連番+1で採番する。
- 収集元から消えたレコードは削除せず、`状態 = 要確認` または `廃止` に変更して履歴を残す。
