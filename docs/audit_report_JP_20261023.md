## 1. 総合判定と重大な問題点（7大欠陥）

従来の [精度管理表.md](精度管理表.md) 上では全項目が「合格」となっていましたが、独立監査の結果、**件数の帳尻合わせ（許容範囲の改ざん）・ゴミデータの大量混入・偽装日付のハードコード・同名異駅の誤結合**など、7つの致命的欠陥が判明しました。

### ① 基準値・許容範囲の改ざんと検査項目の隠蔽（事前調査〜基準設定工程）
* [精度基準マスタ.csv](精度基準マスタ.csv) において、実データの過不足を「合格」に見せかけるため、`主要港湾`（基準125に対し許容最大350）、`主要地方道`（基準2,584に対し許容2,500〜3,100）など恣意的な許容誤差が設定されていた。
* `高速道路IC・施設`（約2,500件）や、制度調査で初期収集対象（`〇`）と明記された `高速バス・空港連絡バス・BRT` および `普通索道（ロープウェイ等）` が基準マスタから除外・放置されていた。

### ② ID管理・検証プログラムの欠陥（スクリプト工程）
* [id_manager.py](../scripts/common/id_manager.py) の `load_table()` が既存CSV読み込み時に名称（`name_ja` / `name_local`）を辞書登録しないバグがあり、再実行時にID重複・約1,800件の連番飛びを引き起こしていた。
* [admin.py](../tools/admin.py) の精度検証が `状態`（現存/廃止）を一切フィルタせず、外部キー整合性や座標・エッジ異常も検査していなかった。

### ③ 外部キー参照整合性の崩壊（幽霊ID・未紐付け）
* [transport_routes.csv](../data/master/transport_routes.csv) において、一般国道全459件が `JP-OP-000288`、高速道路・地域高規格道路全219件が `JP-OP-000279` を参照しているが、[operators.csv](../data/master/operators.csv) の日本の最大IDは `JP-OP-000278` であり、**計678路線が存在しない幽霊事業者IDを参照**している。
* 主要地方道全2,584件は `operator_id` が100%空欄。
* [nodes.csv](../data/master/nodes.csv) の多数の空港・港湾・ICが、所在市区町村ではなく都道府県ID（`JP-MN-000001`〜`000047`）に直接紐付けされている。

### ④ 鉄道路線への大量のゴミデータ混入と「現用・JR北海道」ハードコード
* [transport_routes.csv](../data/master/transport_routes.csv) の鉄道路線（891件）に、Wikipediaから無差別取得された以下のゴミデータが混入し、しかも大半に **`状態=現用`・`operator_id=JP-OP-000001`（JR北海道）が機械的にハードコード**されている。
  * **蒸気機関車（車両）**: `国鉄C11形蒸気機関車227号機`、`静岡鉄道B15形蒸気機関車`
  * **博物館・遊具**: `碓氷峠鉄道文化むら`、`上野動物園のエコライド`、`Zippar`
  * **一般概念・法律・議連**: `地方交通線`、`赤字83線`、`鉄道敷設法別表第11号`、`日本の高速道路`、`高速道路建設推進議員連盟`
  * **戦前の南樺太（サハリン）路線**: `樺太東線`、`樺太西線`、`南樺鉄道線`
  * **未成線・構想**: `弾丸列車`、`富士山における鉄道構想`、`エイトライナー`、`メトロセブン`
  * **廃止路線**: `士幌線`、`東急目蒲線`、`御殿場馬車鉄道`、`京都市電` 等多数

### ⑤ 主要属性カラムの100%空欄と偽装日付のハードコード
* **偽の日付の一律ハードコード**:
  * 全市区町村（1,918件）に `開始日=1970-01-01`
  * 全都道府県（47件）に `開始日=1871-08-29`
  * 全アメダス観測点（1,300件）に `開始日=1974-11-01`
* **100%空欄の項目**:
  * 自治体の `面積_km2`・`人口`、事業者の `法人番号`・`設立日`、路線の `起点ノード_id`・`終点ノード_id`・`営業キロ`・`軌間`・`電化方式`・`開始日`、駅・空港・港湾・IC・道の駅の `よみ_かな`・`開始日`。

### ⑥ ネットワーク・トポロジーの未構築（99.86%の路線がエッジ0件）
* 日本の全4,169路線のうち、[edges.csv](../data/master/edges.csv) にエッジが存在するのはわずか **6路線（226エッジ）のみ**。残り **4,163路線（99.86%）および約14,650ノード（98.4%）が孤立状態**。

### ⑦ 同名異駅の取り違えによる超長距離ワープエッジ（最大964km）
* 6路線だけ生成された [edges.csv](../data/master/edges.csv) でも、駅名の文字列のみで単純結合したため、全国の同名異駅にワープ結合されている。
  * **山手線**: 神田駅が**長崎県佐世保市の神田駅**（距離964.2km）、大塚駅が**広島市のアストラムライン大塚駅**（距離680.1km）に結合。
  * **東北新幹線**: 大宮駅が**京都市の阪急大宮駅**（距離373.6km）、福島駅が**大阪市の福島駅**（距離482.4km）に結合。
  * **山陽新幹線**: 小倉駅が**京都府宇治市の近鉄小倉駅**（距離513.6km）に結合。
  * **大阪環状線**: 大正駅が**長崎県雲仙市の大正駅**（距離526.0km）に結合。
  * **函館本線**: 山崎駅が**愛知県稲沢市の名鉄山崎駅**（距離836.0km）、森林公園駅が**埼玉県の東武森林公園駅**（距離798.6km）、高砂駅が**東京都の京成高砂駅**（距離828.9km）に結合。

## 3. 是正・再構築に向けた改善勧告

1. **公的オープンデータ（国土数値情報・e-Stat・気象庁XML）への全面切り替え**:
   * Wikipedia頼みの無差別スクレイピングを廃止し、国土交通省「国土数値情報（鉄道 N02/N05、高速道路 N06、緊急輸送道路 N10、道の駅 P35、空港 C28、港湾 C02、フェリー航路 N09、バス N07）」および気象庁XML定義ファイルを一次ソースとすること。
2. **偽装データの即時撤去と正確な属性付与**:
   * `1970-01-01` 等のダミー日付、蒸気機関車・博物館等のゴミレコード、重複港湾・廃止空港の誤登録をすべて除去すること。
3. **同一路線内ノード限定による全路線エッジの正確な自動構築**:
   * 駅名単体での全国検索結合を禁止し、路線（`route_id`）に所属するノード群の空間順序・公式駅順に基づいて全路線のエッジを構築すること。
4. **`精度基準マスタ.csv` と検証スクリプト（`tools/admin.py`）の厳格化**:
   * 恣意的に広げられた許容誤差を公的基準値に戻し、外部キー実在検査・都道府県直接紐付け禁止・エッジ距離異常検出・ダミー日付検出を品質ゲートに実装すること。
